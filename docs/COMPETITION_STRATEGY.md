# ClearCart — Judge-Facing Competition Strategy (Nov 9, 2026)

> This is an evidence-led submission plan, not a claim of prize eligibility, completed payment, or an entry. This project is **not** the owner's OMEGA or bounty work.

## North star: a comprehensible, complete experience

**Product proposition:** **ClearCart — From intention to intelligent checkout.**

**Opening hook:** "Shopping usually starts with a product search. What if it started with what you actually need—and the amount you can afford?"

**Proof line:** **Describe a goal → Receive an explainable budget-checked plan → Account for what you own → Explicitly approve a PayPal sandbox purchase.**

**Emotional concept:** *Control feels better than guesswork.* A user should understand every purchase recommendation before any checkout. The film must show **real pixels from the running product**.

### Positioning discipline
- **Audience:** Someone starting a first kitchen, study corner, basic tool kit, or portable lighting setup on a limited budget. Only these categories are currently supported.
- **Problem:** Translating an everyday task into a coherent starter cart can be tedious, and budget fit is often unclear. This is a product hypothesis, not validated market research.
- **Specific solution:** A modest trained intent classifier + exact subset optimizer + transparent reasoning + human-authorized PayPal sandbox checkout.
- **Novelty claim:** An *integration and UX framing* that begins with a need rather than a SKU, not an invention of shopping optimization or of AI classification.
- **Outcomes:** Demonstrate correctness for **one real test case**, not speculative savings, conversion uplifts, retention, or model accuracy.
- **Safe language:** "AI-assisted," "synthetic demo catalog," "test-money checkout," "the user approves." **Avoid:** "universal AI shopping agent," "real-time prices," "guaranteed savings," "hands-free purchases," "production payments," "fully autonomous agent."

## How the official judging rubric should change implementation priorities

Stage One is pass/fail viability: meaningfully use both PayPal and AI. Stage Two has **five equally weighted criteria**. Official source: https://paypalaihackathon.devpost.com/rules

| Criterion | What ClearCart can prove | Best evidence to show | Critical vulnerability to close |
| --- | --- | --- | --- |
| Technological implementation | CPU-trained multinomial Naive Bayes intent routing; exact cents budget optimization; real PayPal Orders v2 sandbox orchestration with verification controls | Short truthful architecture animation *plus actual checkout* | Current provider tests are simulated; genuine capture is pending |
| Design | Coherent responsive task-first form, owned-item controls, explained line items, remaining budget, explicit approval | Readable hero and live before/after comparison | Browser visual/mobile/keyboard QA pending |
| Potential impact | Clear target user and clear budget guardrails | First-apartment kitchen story, before-and-after | No user study or financial impact measurement |
| Innovation/idea | Start from intent and constraints instead of shopping by individual SKU; explain choices and preserve buyer control | One continuous goal-to-checkout story | Avoid claiming proprietary world-first algorithm |
| Presentation | Short compelling narrative, beautifully readable browser demo, real PayPal sandbox evidence | Professional sub-three-minute cut and video thumbnail | Production must not obscure the real app |

## Prize-selection logic

Relevant non-sponsor categories: first/second/third overall, **Best Demo Delivery**, **Best Use of PayPal + AI**, **Most Impactful**, **Most Creative**, and potentially **Best Use of Agentic Commerce**. Do not assert autonomous agency that the app lacks. Only select categories where rules/forms actually permit selection and verified implementation qualifies. Sponsor prizes require genuine inclusion of the particular sponsor's tools; do not add a vendor only to chase a prize if it threatens deadline or reliability.

## Prioritized work, in order

**P0 — Contest-validity blockers (before film polish):**
1. Genuine PayPal sandbox OAuth, order creation, buyer approval, capture confirmation, and dashboard verification, with no real funds.
2. Functional run path for judges; publicly accessible source, MIT license, Node >=22 and `npm ci && npm test && npm run build && npm run dev`; hosted owner-private preview is not independently usable.
3. Actual public YouTube MP4 shorter than 180 s; complete Devpost fields; acceptance before Nov 12 at 12:00 Pacific.

**P1 — Make quality credible:**
- Real Chromium-based screenshot/movie capture, 16:9 with legible type.
- Screenshot verified design/interaction on desktop and mobile; ensure keyboard and focus behavior do not regress.
- Crisp story with authentic output; speak only to current four supported categories.
- Capture evidence of safeguards: synthetic catalog, exact budget, owner-exclusion, PayPal user approval, verified amount/status.
- Closed captions and thumbnail suitable for YouTube and Devpost.

**P2 — Polish if time remains:**
- Simple camera crop, callouts to the actual cart, art-directed interstitials, sound design using self-created/licensed assets.
- Additional sponsor integration **only** if real and meaningful; never at the expense of P0.
- More ambitious AI model or performance benchmark **only** if measured and reproducible, not decorative claims.

## Red-team review — anticipated judge objections

1. **"The AI is just a tiny classifier."** Acknowledge: small, deliberately constrained task classifier; deterministic optimizer keeps outputs inspectable. Do not imply foundation-model reasoning at runtime. Improvement after hackathon would be broader intent evaluation.
2. **"The catalog isn't real."** Acknowledge: synthetic prices/products; no inventory, taxes, shipping or fulfillment. The point of the prototype is the decision-to-approved-payment experience.
3. **"Was there really a PayPal transaction?"** Link non-sensitive verified sandbox evidence; blocked if only mocked. Checkout is human-approved. Sandbox is not production.
4. **"Could I run this?"** Public source + proven run instructions or truly judge-accessible demo. Owner-private URL alone fails.
5. **"Does it save money?"** Not scientifically established; say "respects the entered limit" not "saves X%".
6. **"Is it agentic?"** It assists with a constrained planning task and user-approved checkout; do not claim agentic tool orchestration unless implemented and evidenced.
7. **"Is the video staged?"** Every described functional state corresponds to the actual running app. Editorial graphics must be clearly separate from product footage.

## Ship decision

An adequate, complete and verified demo **beats** an extraordinary but unfinished film. Hold a frozen, truthful fallback capture before attempting enhancements. Do not represent drafts, mock screenshots, fake confirmations, or stubbed responses as real. Evidence of a valid submission must include actual Devpost entry URL and acceptance confirmation.
